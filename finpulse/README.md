# FinPulse

A stock market monitoring platform tracking 20 NSE-listed Indian companies —
live/historical fundamentals, a REST API, an interactive dashboard, and a
LangGraph-powered chat assistant that answers questions using the app's own data.

## Architecture

```
finpulse/
├── data/fetch_stock.py     # yfinance wrapper: price, market cap, P/E, EPS, history
├── db/                      # SQLAlchemy models + session setup (SQLite by default)
│   ├── database.py
│   └── models.py            # Company (latest snapshot) + PriceHistory (daily rows)
├── ingestion/
│   ├── companies.py         # List of 20 tracked NSE tickers
│   └── ingest.py             # Fetches + upserts data into the DB
├── api/                      # FastAPI backend
│   ├── main.py
│   ├── schemas.py
│   └── routes/
│       ├── stocks.py         # GET /stocks, GET /stocks/{ticker}
│       └── summary.py        # GET /market-summary
├── chatbot/                  # LangGraph agent + REST wrapper
│   ├── tools.py               # DB-query tools the agent can call
│   ├── agent.py                # ReAct agent, system prompt enforces short answers
│   └── routes.py                # POST /chat
├── dashboard/app.py           # Streamlit UI: charts, comparison, chat
├── requirements.txt
└── .env.example
```

## Data flow

1. `ingestion/ingest.py` calls `data/fetch_stock.py` for each of the 20 tickers,
   writing the latest snapshot into `companies` and appending daily rows into
   `price_history` (de-duplicated on ticker+date).
2. `api/main.py` serves that data over REST.
3. `dashboard/app.py` (Streamlit) and the chatbot both consume the API —
   neither touches the database directly.
4. The chatbot (`chatbot/agent.py`) is a LangGraph ReAct agent: it calls
   tools that query the DB directly (not the open web) and is constrained
   by its system prompt to answer in 2–3 short sentences.

## APIs / libraries used

- **yfinance** — market data source
- **SQLAlchemy + SQLite** — storage (swap to Postgres/Supabase via `DATABASE_URL`)
- **FastAPI** — REST API
- **Streamlit + Plotly** — dashboard, candlestick charts
- **LangChain + LangGraph + Claude (Anthropic)** — chat assistant

## Setup

```bash
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

pip install -r requirements.txt
cp .env.example .env         # then fill in ANTHROPIC_API_KEY
```

## Run order

```bash
# 1. Create tables
python -m db.models

# 2. Populate data (takes a few minutes, has a delay between tickers to avoid rate limits)
python -m ingestion.ingest

# 3. Start the API
uvicorn api.main:app --reload

# 4. Start the dashboard (separate terminal)
streamlit run dashboard/app.py
```

Dashboard: http://localhost:8501
API docs (auto-generated by FastAPI): http://localhost:8000/docs

## Features implemented

- Live + historical data for 20 NSE companies (price, market cap, P/E, EPS)
- SQLite database with two tables (current snapshot + historical daily rows)
- 4 REST endpoints: `/stocks`, `/stocks/{ticker}`, `/market-summary`, `/chat`
- Interactive dashboard: candlestick charts, company comparison, market summary
- LangGraph chatbot answering questions from the app's own data, short by design

## Challenges faced

- Yahoo Finance rate-limits repeated requests during development — mitigated
  with `requests-cache` and a delay between tickers during ingestion.
- Some fundamentals (P/E, EPS) are `None` for certain companies — handled with
  nullable DB columns and `.get()` lookups instead of direct key access.

## Future improvements

- Move deployment to Postgres/Supabase for persistence across restarts
- Add scheduled ingestion (cron / APScheduler) instead of manual runs
- Add authentication and per-user watchlists
- Expand chatbot tools to support sector-level comparisons
